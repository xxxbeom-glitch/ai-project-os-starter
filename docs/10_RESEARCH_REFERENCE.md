# 10 RESEARCH & REFERENCE

## 목적
0에서 상상으로 만들기보다, 이미 검증된 사례와 공식 문서를 먼저 찾고 우리 조건에 맞게 재구성한다.

## Reference First
기본 순서:
```text
Search → Compare → Extract → Synthesize → Build → Verify
```

## 조사 우선순위
1. 공식 문서
2. 실제 제품
3. 신뢰할 수 있는 리서치/업계 자료
4. 오픈소스/샘플 코드
5. 커뮤니티 경험담

커뮤니티 글은 유용하지만 사실 검증 없이 공식 기준처럼 사용하지 않는다.

## Super Sample
이 문서에서 `Super Sample`은 공식 표준 용어가 아니라 교육용 표현이다.

여러 좋은 사례에서 각각의 장점을 뽑아 우리 프로젝트의 제약에 맞는 하나의 기준 샘플로 합성한다.

예:
- A 서비스: 저장 흐름이 빠름
- B 서비스: 검색 결과가 명확함
- C 서비스: 카테고리 UX가 단순함
- 우리 조건: 5초 안에 저장

표면을 그대로 복사하지 않고 **왜 잘 작동하는지**를 먼저 분석한다.

## Research Agent 출력 형식
```text
Question:
Source:
Source date:
Verified fact:
Interpretation:
Risk / limitation:
Recommendation:
```

## 금지
- 출처 없는 수치를 사실처럼 작성
- 오래된 문서를 최신 정책처럼 사용
- 검색 결과 snippet만 보고 결론 확정
- 경쟁사 UI를 그대로 복제
- 라이선스 확인 없는 코드/asset 복사

## 완료 조건
중요한 기술/정책 결정은 최소 한 개의 공식 또는 1차 출처를 확인한다.
